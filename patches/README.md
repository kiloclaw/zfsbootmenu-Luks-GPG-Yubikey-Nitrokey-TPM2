# Patched crates

Crates the workspace builds with a change of ours, until their authors release it. Each is the crate as crates.io
publishes it, with the change applied, and `[patch.crates-io]` in the root `Cargo.toml` points at it. `cargo vendor`
leaves this directory alone: it owns `vendor/` only ([docs/dev/dependencies.md](../docs/dev/dependencies.md)).

| Crate | Change | Offered upstream |
| --- | --- | --- |
| `brush-parser` 0.4.0 | [brush-parser-case-in-substitution.patch](brush-parser-case-in-substitution.patch): in a command substitution, the `)` that ends a `case` pattern (`a\|b)`) no longer closes the substitution, as in bash. Without it, brush cannot read `zfsbootmenu-core.sh`, which the recovery shell sources, nor any script with such a `case` inside `$( )`. The tokenizer tracks the `case` commands of the substitution, and the word parser asks the tokenizer where the substitution ends. With tests; brush's 2,067 compatibility cases give the same results with it | To be offered to [reubeno/brush](https://github.com/reubeno/brush) |
| `brush-builtins` 0.2.0 | [brush-builtins-kill-signal-numbers.patch](brush-builtins-kill-signal-numbers.patch): `kill` takes signal numbers, as in bash: `kill -9 <pid>` and `kill -s 9 <pid>` failed with "invalid signal name", as only names were looked up. Found by the VM test `runtime-rust-console`, which ends the console with `kill -9` | To be offered to [reubeno/brush](https://github.com/reubeno/brush) |
| `brush-interactive` 0.4.0 | [brush-interactive-terminal-control.patch](brush-interactive-terminal-control.patch): the interactive shell keeps the terminal until it ends, and then gives it back to the process group that had it, as bash does. `InteractiveShell::new` dropped the guard that `TerminalControl::acquire` returns at once, so brush, which leads a process group of its own when its parent is not a session leader, left that group in the foreground when it exited: the menu that opened the recovery shell could then read no key, and every `exit` led back to a shell. Found by the review before the console's M4 | To be offered to [reubeno/brush](https://github.com/reubeno/brush) |
| `vte` 0.15.0 | [vte-linux-console-and-xtversion.patch](vte-linux-console-and-xtversion.patch): the parser ends the Linux console's palette sequences, which have no terminator (`ESC ] P nrrggbb` sets colour n, `ESC ] R` resets colours 0 to 15), so that the text after them stays text; `Handler` gets three methods, which do nothing by default: `report_version` for XTVERSION (`CSI > q`), `set_linux_cursor` for the Linux cursor size (`CSI ? n c`) and `linux_private` for the Linux console's private sequences (`CSI n ]`, those of `setterm`). With tests | To be offered to [alacritty/vte](https://github.com/alacritty/vte) |
| `alacritty_terminal` 0.26.0 | [alacritty_terminal-linux-console-blink-reverse-version.patch](alacritty_terminal-linux-console-blink-reverse-version.patch): `Config` names the terminal (`name`, `version`) for XTVERSION and the secondary device attributes; SGR 5 and 6 set a new cell flag, `Flags::BLINK`, which SGR 25 clears; DECSCNM (`CSI ? 5 h`) sets a new mode, `TermMode::REVERSE_SCREEN`, and draws the screen again; the Linux cursor size sets the cursor's shape (1 hides it, 2 and 3 an underline, the others a block, 0 the default); `CSI 8 ]` makes the current colours the default ones, which SGR 0, 39 and 49 then give, until a reset; `Term::wipe_history` overwrites the lines of history beyond those kept, and clearing the history (`CSI 3 J`) overwrites them too, so that what scrolled off does not stay in freed memory. With tests; the crate's 136 tests and 45 reference tests pass with it. It needs the `vte` patch | To be offered to [alacritty/alacritty](https://github.com/alacritty/alacritty) |

To refresh a patched crate for a new release: unpack the release's `.crate` file here, apply the patch (`patch -p1`
in the crate's directory), run its tests (`cargo test` there), and drop the patch once a release has the change.
